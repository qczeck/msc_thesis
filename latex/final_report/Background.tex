\ourchapter{Background and related work}\label{ch:background}

\section{Self-supervised visual representation learning}\label{sec:ssl}
Self-supervised learning (SSL) is a learning paradigm where the supervisory task is generated from data itself, without needing a human-assigned label~\cite{sslsurvey}. SSL approaches can be grouped into either generative or discriminative. The goal of generative approaches is to learn distributions over a collection of data in pixel space, whereas discriminative approaches' goal is to learn representations of data with high discriminative power (similarly to supervised approaches, just without human labels). PART and the extension proposed in this project are examples of discriminative approaches. 

Relevant categories include:
\begin{itemize}
\item Instance discrimination: This method relies on taking an image, augmenting it in different ways and then matching different augmentations coming from the same origin while contrasting them when the origins differ. SimCLR ~\cite{simclr} is a classic example, where images are augmented via random crops, colour distortions, and blurs and then the model has to learn to match and contrast the views.
\item Masked image modelling: This method works by splitting an image into non-overlapping patches, masking some of them, and asking the model to generate the missing patches. It is an example of generative SSL. One of the first examples of masked image modeling was MAE ~\cite{mae}.
\item Puzzle solvers: Most tasks in this category trace their lineage to jigsaw ~\cite{jigsaw} which introduced a pretext task that requires the model to unshuffle pieces of an image to obtain the original image.
\item Others: Many tasks do not fit neatly in the mainstream categories. Context prediction ~\cite{context2015} is one example that falls in this category.
\end{itemize}

Later in the survey, the authors group the discriminative frameworks into four categories: 1) Clustering, 2) Contrastive learning, 3) Distillation, and 4) Information-maximisation. RoPART does not really fall into any of the above, it supervises spatial-relational structure not really touched by any of the categories - it revives mostly written-off pretext task line.

SSL methods are evaluated most commonly in one of three ways:
\begin{enumerate}
\item Fine-tuning the entire model - this is the way RoPART is evaluated.
\item Linear evaluation/probing: this works by freezing all trainable parameters and adding a linear layer mapping features to predictions.
\item K-nearest neighbours evaluation on learned features.
\end{enumerate}


\section{Vision transformers}\label{sec:vit}
RoPART follows the SSL Computer Vision consensus and uses a Vision Transformer (ViT) ~\cite{vit}.  A vision transformer splits an image into fixed size patches, linearly embeds them, adds positional embeddings, and then passes the input through a transformer encoder with self-attention layers. Because the correspondence between patch and token is one-to-one and survives the encoder, the final representation of patch $i$ remains addressable - this allows a target to be attached to a patch and a pair of patches to be indexed and compared. Furthermore, positional embeddings are an additive, learned input - that makes them removable. Finally, attention is permutation-equivariant, so with no positional embeddings, the model sees and unordered set of patches. Note: the ViT-S configuration used in this model actually comes from DeiT ~\cite{deit} (VIT ~\cite{vit} only defines Base/Large/Huge).

\section{The position-prediction lineage}\label{sec:position-prediction}
The idea that the context could be a powerful self-supervisory signal comes from text processing. Having a model learn to predict the words surrounding any given word could lead to powerful, transferable insights. Doersch et al~\cite{context2015} extended this idea to images: given a reference patch and one of its eight neighbours on a $3\times3$ grid, a Convolutional Neural Network (CNN) must classify, which of the eight positions the neighbour occupies (Figure~\ref{fig:doersch}). This works because, for example, to predict that a patch containing a cat's left ear is to the top left of a patch containing a cat's nose the model has to build a correct representation of an object and its constituent parts. The supervision is coarse, the position is represented as a choice among eight discrete cells, so the target set is finite. The authors also had to face an issue where the model would take a shortcut: instead of learning the semantics, the network would exploit chromatic aberration to locate the patches relative to the lens axis - this is a very similar kind of problem that RoPART faces where the model would potentially learn the blur signature instead of the semantics.

This idea was extended further by~\cite{jigsaw} where the pretext task was to solve a "jigsaw" puzzle where the model had to reassemble a picture that was sliced into patches along a grid and then shuffled (Figure~\ref{fig:jigsaw}). Once again, by the learned representations used to solve this pretext task captured semantically relevant content.

In the transformer era, Computer Vision also took inspiration from NLP, this time leveraging masking. Masked AutoEncoder~\cite{mae} constructs a pretext task by masking out a subset of patches at random and then asks a vision transformer to reconstruct the missing patches - this is a generative approach operating at pixel level (Figure~\ref{fig:mae}). Notably, the patches are still confined to a fixed grid, but the position embeddings are dropped - this suggests that geometry can substitute for explicit position embeddings (which is the case in RoPART). Furthermore, the authors show that the models respond well to surprisingly high masking ratio of up to 75\%. RoPART performs masking indirectly, by randomly sampling the $x,y$ coordinates of each patch (and thus the space not covered by sampled patches is considered masked). What differs is that MAE's cost is generative and at pixel-level. 

MP3~\cite{mp3} is an example of vision transformer solving a position prediction pretext task - its goal is to predict the absolute position of a patch on a grid (Figure~\ref{fig:mp3}). The authors achieve that by removing positions, selecting random context tokens and then tasking the model with predicting absolute positions for each token. The main drawback of this approach is that patches are confined to a grid, which reduces the target set of the model's predictions - it is fundamentally an easier task.

While MP3 drops all position embeddings, DropPos~\cite{droppos} drops a subset of positional embeddings, keeping the remaining ones as "anchors" (Figure~\ref{fig:droppos}). The authors argue that models not exposed to positional embeddings (such as MP3) introduce discrepancies between pretraining and finetuning, hurting downstream performance. A relevant finding to RoPART is that visually similar patches have ambiguous positions and forcing exact recovery is worse than relaxing the target and introducing position smoothing and attentive reconstruction. RoPART may also run into this issue when selecting e.g. patches of the sky.

Crucially, all methods mentioned above are confined to a fixed grid and predict positions or reconstruct masked content on that fixed grid. 


\section{PART in detail}\label{sec:part}
\textbf{PA}irwise \textbf{R}elative \textbf{T}ranslations~\cite{part} is a pretraining method that is not based on a grid (Figure~\ref{fig:part}). Given that this paper is the base of this project, a more detailed treatment is required.

\begin{figure}[htbp]
  \centering
  \includegraphics[width=\textwidth]{PART.jpg}
  \caption[The PART pipeline]{The PART pipeline~\cite{part}: patches are sampled at
  random continuous (off-grid) positions and embedded by a ViT \emph{without}
  positional embeddings; a cross-attention relative encoder then predicts the
  relative translation $(\Delta x,\Delta y)$ between sampled patch pairs, supervised
  with an MSE loss. The geometry of the pair, rather than an absolute grid position,
  provides the supervisory signal. Figure reproduced from~\cite{part}.}
  \label{fig:part}
\end{figure}

First, given an image, $N$ random patches are extracted, where the top-left coordinates of patch $s$, $(x_s,y_s)$ are drawn uniformly across the image. The patches are of size $P$ (therefore, the bottom-right coordinates are given by $(x_s+P,y_s+P)$). Because the patches are sampled uniformly and off-grid, masking occurs naturally. Note that no positional embeddings are used.

The goal is to learn the translation between any pair of patches (considering the width $w_\text{ref}$ and height $h_\text{ref}$ of the reference patch):

$$\theta_{\text{ref},\text{tgt}}=\begin{bmatrix} \Delta x \\ \Delta y \end{bmatrix}_{\text{ref},\text{tgt}}=\begin{bmatrix} (x_\text{tgt}-x_\text{ref})/w_{\text{ref}} \\ (y_\text{tgt}-y_\text{ref})/h_\text{ref} \end{bmatrix}_{\text{ref},\text{tgt}}$$

Overall, $N=\frac{H\times W}{P^2}$ patches are sampled (this is the same number that a grid would produce) and reshaped into the original image size $\hat{I}\in \mathbb{R}^{H\times W\times C}$ where $C$ is the number of channels. The patches are then flattened and linearly projected into $X\in\mathbb{R}^{N\times d}$ (standard ViT procedure). $X$ then goes through ViT to obtain learned embeddings $X'\in \mathbb{R}^{N\times d}$.

To construct a relative encoder architecture, random subset of patch indices is sampled, $S\in\mathbb{N}^{2\times \#\text{pairs}}$, with $S_0$ as the index of reference patches and $S_1$ as the index of target patches. Afterwards, the reference and target embeddings are gathered and concatenated to obtain $\hat{X}=\text{concat}(X'_{S_0},X'_{S_1})\in\mathbb{R}^{\#\text{pairs}\times 2d}$. Finally, $\hat{X}$ goes through a linear projection to bring it to $\hat{X}\in \mathbb{R}^{\#\text{pairs}\times d}$ so each pair is now $d$-dim query vector. $X'$ is fed as both the key and value. This yields attention: $\hat{\theta}=\text{attn}=\text{softmax}(\frac{\hat{X}X'^T}{\sqrt{d}})X'$. After one final linear projection, one obtains $\hat{\theta}\in\mathbb{R}^{\#\text{pairs}\times2}$.

Finally, mean squared loss is used:
$$\mathcal{L}_{MSE}=\frac{1}{2\times\#\text{pairs}}\sum^2_{k=1}\sum^{\#\text{pairs}}_{m=1}(\theta_{mk}-\hat{\theta}_{mk})^2$$

The authors also show that the framework is extensible by adding relative scale and aspect ratio terms $\Delta w,\Delta h$. This extends the objective to:
$$\theta_{\text{ref},\text{tgt}}=\begin{bmatrix} \Delta x \\ \Delta y \\ \Delta w \\ \Delta h \end{bmatrix}_{\text{ref},\text{tgt}}=\begin{bmatrix} (x_\text{tgt}-x_\text{ref})/w_{\text{ref}} \\ (y_\text{tgt}-y_\text{ref})/h_\text{ref} \\ w_\text{tgt}/w_\text{ref} \\ h_\text{tgt}/h_\text{ref} \end{bmatrix}_{\text{ref},\text{tgt}}$$
The authors note that this delays the convergence of $\Delta x,\Delta y$ compared to the baseline. Note that it also reduces performance on downstream tasks, reducing the accuracy on e.g. ImageNet classification from 82.7 to 82.6. The authors attribute that to increased parameter and objective complexity - given that RoPART does the same, this was cautiously observed. 

Crucially, the model learns symmetrical relationships, i.e. if patch $P_i$ predicts $(\Delta x,\Delta y)$ relative to $P_j$, then $P_j$ predicts $(-\Delta x,-\Delta y)$ relative to $P_i$. The method is also capable of estimating patch uncertainty by checking the agreement of different reference patches on the relative position of a target patch - with "easy" patches being consistently placed at the same location.

In terms of results, it beats DropPos, MPC, and MAE on COCO detection (42.4 vs 42.1, 41.8, 40.1 respectively). I also beats the three on PhysioNet sleep staging benchmark. On CIFAR-100, the ViT-S version shows slightly lower accuracy than MAE and MP3, but at half the budget (measured by epochs). It appears that PART outperforms its peers on tasks requiring spatial understanding rather than global classification.

The authors conclude the paper with several future directions such as hierarchical multi-scale learning, extensions to other tasks, and - most importantly to this project - modelling rotations.


\section{Rotation in self-supervision}\label{sec:rotation-in-ssl}
RoPART takes the stance opposite to equivariant architectures - instead of building in symmetry like in ~\cite{gcnn} it treats rotation as a recoverable supervisable signal. Invariance is the correct choice when orientation is a nuisance factor, but when orientation is the target it is not. That being said, rotation can be an SSL objective in itself. In RotNet~\cite{rotnet} the whole image is rotated globally by $0^{\circ},90^{\circ},180^{\circ},270^{\circ}$ and the network must classify which of the four rotations was applied (Figure~\ref{fig:rotnet}). This approach does not introduce low-level visual artefacts and exhibits well-posedness. Interestingly, adding rotations of $45^{\circ},135^{\circ},225^{\circ},315^{\circ}$ degrades CIFAR-10 classification accuracy - the authors attribute this degradation to the fact that 8 rotations are not distinguishable enough and/or the fact that visual artefacts are introduced - this is a key finding directly relevant to adding continuous rotations in RoPART. Later work refined the signal - Feng et al.~\cite{rotdecouple} decouple rotation-dependent from rotation-invariant features. On the other hand, Misra and van der Maaten~\cite{pirl} argue that representations should be invariant to such transformations rather than predict them, arguing for better performance in semantic recognition tasks. Across this line of research, rotation is a global, absolute, image-level signal predicted as a few discrete classes. The orientation studied here is instead relative between a patch pair, local, and continuous; to the best of current knowledge no prior work supervises relative orientation between off-grid patch pairs.

\section{Orientation-sensitive tasks and their metrics}\label{sec:orientation-tasks}

We define a task to be orientation sensitive when the label is an angle or if the scene has no canonical `up'. To highlight the difference, consider classification, where orientation is treated as a nuisance factor. Both are important, hence why the pretrained models are assessed on both classification (to ensure no degradation) and an orientation sensitive task. 
The downstream task chosen for this project is Horizon Lines in the Wild~\cite{hlw}, a dataset of 100\,553 images in which the goal is to estimate the horizon line of a single image. Figure~\ref{fig:hlw} shows a representative example: the labelled horizon is both tilted, so that the orientation channel carries real signal, and largely occluded, so that it cannot be read off directly from a visible sky--ground boundary. The dataset contains 100,553 images. Note that the baselines perform classification into 100 bins rather than regressing the angle - this is different to the RoPART approach. Each image target comes parametrised as $(\theta,\rho)$ which is the angle the horizon makes with the x-axis and the perpendicular distance from the origin of the horizon line, respectively. This parametrisation is unchanged when finetuning models pretrained using RoPART. Crucially, $\theta$ is in-plane orientation and $\rho$ is translation-like. This means that $\theta$ can act as a treatment channel and $\rho$ can act as a control channel when comparing models trained with rotation to baseline. Note that the metric to measure horizon detection error proposed by the authors is the area under the curve of the cumulative histogram of errors - this report finds that the translation part of the error greatly outweighs the rotation part.

\section{Positioning RoPART}\label{sec:positioning}
RoPART fills the gap that PART ~\cite{part} mentioned, it extends the pretext task from the translation subgroup of planar rigid motion to the entire \SEtwo group. This extension happened because the authors left it as future work and showed that the framework itself is extensible by adding channels. Their finding that extensions delay convergence informed decisions to add complexity to the framework one step at a time to isolate each factor. RoPART differs from prior rotation work as previous work was: \begin{itemize}
\item absolute, focusing on rotation relative to 'up' - RoPART is relative - it looks at rotations between patches.
\item global, rotating entire pictures - RoPAT is local as it rotates patches.
\item discrete, limiting the rotations to a finite set of possible rotations - RoPART treats rotation continuously.
\end{itemize}
The literature so far touched upon two potential validity threats that had to be taken into account. \begin{enumerate}
\item Interpolation confound. An example of such a confound was chromatic aberration in Doersch et al. ~\cite{context2015}. In RotNet ~\cite{rotnet} the authors hypothesised that poor performance at angles such as $45^\circ$ could be attributed to rotation artefacts.
\item Orientation recoverability. This is what DropPos ~\cite{droppos} found for position where visually ambiguous patches that carry little information degraded performance. With rotation in the mix, textureless or symmetric patches may introduce similar issues.
\end{enumerate}
In terms of evaluation, only full finetuning is performed, following the practice in PART ~\cite{part}. HLW dataset has built in specificity control and its results will be attributed appropriately. Finally, a different metric will be used to measure the error rather than the established AUC.
