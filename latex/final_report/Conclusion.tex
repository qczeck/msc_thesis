\ourchapter{Conclusions and future work}\label{ch:conclusion}

\section{Findings}\label{sec:findings}
In this section we will summarise what the project established:
\begin{itemize}
\item Relative orientation is learnable under RoPART pretext at $P=32$ and $\pm30^\circ$ and the deconfounded arm matches raw so interpolation signature is ruled out.
\item Orientation is not learnable at small patches. $P=4,8,16$ runs all came back null as recoverability at this small of a patch size is too difficult to get.
\item \emph{At the pretext level}, supervising rotation costs nothing in terms of translation performance. \emph{On ImageNet-100} it is also the case that supervising rotation does not cost performance (this time on classification).
\item Rotating pixels without supervision damages the representation on both downstream tasks - it is not a very good data augmentation technique.
\item Wide range is not repaired by supervision like in the narrow case.
\item Pretext structural gates are a poor predictor of downstream utility.
\item Side result: HLW's AUC is structurally $\rho$ dominated ($\approx 28\times$) and blind to the orientation effect.
\item RoPART$\pm30^\circ$ beats the baseline on HLW $\theta$ by $4.2\%$ with the specificity control null, suggesting that improvements are driven by the pretext task design rather than the model being ``better''.
\end{itemize}


\section{Limitations}\label{sec:limitations}
This section will describe the limitations of the project. Below we list them and name measures that would remove them:
\begin{itemize}
\item Only a single dataset per downstream task. Orientation is entirely covered by HLW, classification by ImageNet-100. Currently the results hinge on the type of the task and the specific dataset at the same time. Adding more classification and orientation tasks would allow more general conclusions to be drawn.
\item There is a single value of the rotation bound, $a=30^\circ$ combined with a single patch size, $P=32$ that together give the only point at which the model performs better than the baseline. A full sweep of $a$ could lead to a larger set of suitable bounds, perhaps even being able to decide the optimum.
\item The blur is technically only $96\%$ removed, just shy of $100\%$ which means some blur signature might have slipped through. Adding more controls (e.g. randomised blur which decorrelates it from \dphi{}) would increase the confidence in the statement that blur signature did not play a role.
\item Smaller scale than upstream: PART~\cite{part} used 8 A100 GPUs and ImageNet-1K with $10\times$ as many classes. The scope of this project was deliberately not to replicate the full scale but nevertheless, more compute and more training data is almost always better.
\end{itemize}


\section{Future work}\label{sec:future-work}
Here we discuss the future work that opened up thanks to the findings in this project. One could add \textbf{orientation uncertainty} as a functionality of the method similarly to how upstream featured patch-uncertainty. As a result the model could say which patches have recoverable orientation and the $P=4,8,16$ nulls would be reframed into a prediction the method could make itself. One could also set $c=6$ and \textbf{combine translation, rotation, scale, and aspect ratio} all at once. It would be interesting to investigate whether the channels compose or interfere. Furthermore, this would be directly relevant to the upstream's note that adding scale channel delayed \dxy{} convergence. Finally, \textbf{a sweep of} $\mathbf{w_\varphi}$ would allow to distinguish whether wide-range performance deterioration is a property of the task or the weighting.
